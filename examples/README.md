# Example files

Everything here is synthetic. Authors are fictional, venues are invented, and every DOI uses the DOI Foundation's reserved example prefix `10.1000/`, so nothing resolves to a real paper.

| File | Format | Records | Notes |
|---|---|---|---|
| `web_of_science.ris` | RIS | 6 | Multi-line title and abstract continuations; `SP`/`EP` pages; a `CONF` entry with `T2` |
| `ieee_xplore.bib` | BibTeX | 5 | Braced values, `and`-separated authors, double-hyphen pages, one entry without a DOI |
| `pubmed.nbib` | NBIB/MEDLINE | 4 | Indented continuation lines, DOI in `AID ... [doi]`, `MH` headings as keywords |
| `scopus_export.csv` | CSV | 7 | Scopus column names, UTF-8 byte-order mark, a quoted field containing commas and a line break, doubled quotes, one record without a DOI |
| `sample_review.slrproj` | project file | 22 | The four exports imported and deduplicated, two reviewers, title screening complete with one resolved and one open conflict, abstract screening under way, a search record, PRISMA counts and a partly completed checklist |

Six papers appear in more than one export, so importing all four files and running duplicate detection flags eight records: the shared paper on adversarial robustness appears in all four; four others appear in two exports each with identical or near-identical titles; and one pair differs by a hyphen and a missing DOI, which exercises the fuzzy title pass.

To try the importers, open the application, go to Import & Deduplication, and drop the four export files together. Attribute each to the database in its file name when asked. Then run duplicate detection.

To see every tab populated, go to the Project tab and open `sample_review.slrproj`.

`sample_review.slrproj` is generated by `npm run examples` (`test/make_examples.js`) from the four exports, so it can be regenerated after any change to the project file format.
